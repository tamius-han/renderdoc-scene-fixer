RenderDoc Capture Fixer — user guide

The intent of this tool is to simplify capturing and fixing game meshes with RenderDoc. In order to use it, you will also need either

  1. RenderDoc
    (RenderDoc Scene Exporter addon requires v1.45; older or newer versions may not work)
  2. RenderDoc Scene Exporter
  1. Intel GPA suite
    (windows-only; Internet Archive: allegedly this)

After installing Renderdoc and Renderdoc Scene Exporter addon (or Intel GPA suite), you can start capturing.

By default, Renderdoc saves your game captures to:
  • %TEMP% on Windows, and
  • /tmp/RenderDoc on Linux.

Note that on Linux, /tmp directory usually exists in your RAM. You might want to change capture directory in Renderdoc settings to a folder on your disk.

BTW: If you're exporting with Intel GPA instead, gods of UX have blessed you with not having to know these things.

Capturing the game

  1. Launch Intel GPA
  2. For steam games: in the Executable Path field, enter the path to steam executable.
    For other stores: same, just replace steam with other store's launcher.
    For standalone software: enter the path to the program's executable.
    Note: the 'three dots' button gives you a file picker.
  3. Click Start
  4. If trying to capture a steam game (or a game from a different store), launch the game from the store's launcher.
  5. If you see this in the upper left corner of your screen, everything is set up for capturing game scene:
  6. Capture the scene whenever you want.

Tools like Intel GPA (and RenderDoc, and NinjaRipper) touch the game's rendering pipeline. Some games are a bit sensitive to that, and will crash or even refuse to launch. If your game doesn't launch with Intel GPA, try using RenderDoc. But if neither work ...

TW: while you're probably aware you're in the Belgeek right now, the border with Nerderlands is fast approaching. Take care.

Sometimes, you can work around that by moving your capture spot outside of the game's rendering pipeline. There are two options that allow you to do that (though neither is guaranteed to work for every game):

  1. DXVK
  2. Linux (which is really just DXVK but fancier, where Steam does all the hard work for you)

Don't want to install Linux? You don't have to. Many common Linux distributions can be run directly from a USB flash drive, without having to install them on your computer (although your performance may be limited by your USB flash drive). Choice of Linux distribution is up to you. As of 2026, I suggest CachyOS with KDE. CachyOS because that's what my experience is based on, and KDE because that way your experience will be closest to what you're used to on Windows.

Before you go and make a linux live USB, check ProtonDB to see how well your game is supported. ProtonDB can be a bit hit-or-miss at times, but it's a decent rule of thumb.

When using Linux from a flash drive, install Steam and Renderdoc (note that if you're using Linux from a flash drive, you typically need to re-install software on every boot). If your game library is on C: drive, you can then add it to Steam in Steam settings > Storage > Add drive and then navigating to your steam install folder. If your game is not on C:, then your options are: a) move it to C:, or b) add new library on Steam on one of your disks and re-install it. (I'm 0 for 2 on trying to launch games from my non-C: windows steam library. Restoring from a backup might also work, but is untested. I'm 2-for-2 on launching games from my Windows C: drive library).

If the game refuses to launch on Linux, right click on game and go to Properties -> Compatibility and check the "force use of a specific Steam Play compatibility tool" checkbox. If the game still don't work, try Proton-cachyOS, Proton Experimental, Proton Hotfix, Proton [biggest number], googling or asking ChatGPT (in that order).

  1. Install your game via Steam. If your game is standalone, add it as a non-steam game to steam and set up compatibility tools (proton) as needed.
  2. Make sure the game is running.
  3. Make sure game isn't running via Wayland. At the time of writing this, games won't launch at all under Wayland. Make sure you didn't put PROTON_ENABLE_WAYLAND=1 into the launch options.
  4. Exit steam
  5. Open a terminal (KDE: konsole, other DEs: why don't you use a DE that isn't shit?, WMs: you already know what to do)
  6. Run the following command:
    sudo renderdoccmd vulkanlayer --register --system
    Unless you run Linux from live USB, you only ever need to run this command once per install. This registers renderdoc's vulkan capture system wide, and makes enabling renderdoc capture slightly easier.
  7. Use the following command to launch Steam:
    ENABLE_VULKAN_RENDERDOC_CAPTURE=1 steam
    (this works on CachyOS; other distros may vary)
  8. Launch your game via Steam.
  9. If the game refuses to launch, right click on the game, go to Preferences -> Compatibility and check the "force use of a specific Steam Play compatibility tool" checkbox. Play around with the option. If you're fresh to Linux, consult with Linux advertisement in the windows tab as I won't repeat it here.
  10. If you see this in the upper left corner of your screen, everything is set up for capturing game scene:
  11. Capture the scene whenever you want.

After capture

  1. Select your capture from the list of captures and double-click it
  2. WAIT. Intel GPA takes quite some time to load the capture. Impatiently clicking on the capture when it fails to launch in less than 30 seconds will just open the capture multiple times.
  3. Click on the model you want to export. This will switch the left sidebar to `Pixel history` tab.
  4. In the `Pixel history` tab, select the DrawIndexed call with color that matches the color of the pixel you just clicked. This will highlight parts of the picture in purple. This will also open a second sidebar on the left.
  5. If you see a lot more purple than you expected (e.g. say, if the entire picture turns purple), scroll to Input section of the second bar and click the texture that most resembles your screenshot. The correct option will probably be labelled along the lines of T: (SRV). The line item will also have a thumbnail that isn't just a symbol/icon. If there's multiple options, go and explore.
  6. Click that texture in the Input section of the second sidebar. Once you do, the preview image will change.
  7. Repeat steps 4-6 until only (a part of) the character or other object you want to export gets highlighted.
  8. Control-click on the un-highlighted part, wait for the list of draw calls to update, control-click the draw call with a color square that has the same color as the pixel you clicked. Repeat until everything you want to export is purple.
  9. If you worry that you're missing some parts of your character that are obstructed from view, switch the left sidebar to API Log tab and add draw calls near your already-selected draw calls to selection.
  10. Once satisfied with your selection, click on the Geometry section in the Output section of the second sidebar on the left. Then, click the export button (upper right corner of the preview panel) and save your scene as `scene.obj`
  11. You have probably noticed that everything appeared very squished in the preview panel. To fix that, you also need to pick a landmark.
    Landmark is an object that is not rigged or otherwise distorted. Unselect your character and click on some object you can see the same way you selected your character. You need exactly ONE (1) DrawIndexed call. Click Geometry in the Input section of the second sidebar on the left. Rotate the object a bit in order to verify that the object has the exact same shape as it has in the game. If it doesn't, you need to pick a different draw call. If it does, export this input geometry and save it as landmark-source.obj.
  12. Click Geometry in the Output section of the second sidebar on the left. Export this geometry and save it as landmark-output.obj.
  13. Drag the three files you've just exported (scene.obj, landmark-source.obj, and landmark-output.obj) into this app.
  1. File > Open Capture. Navigate to your capture directory and open the capture.
  2. Make sure Renderdoc Scene Exporter extension is enabled.
  3. Click Tools > Export scene and do the needful™. Create a new folder and export the scene into said folder.
  4. Drag the folder into this app.

Using this tool

If you're reading this, the standard FAFO approach (that is: messing around the program in order to find out) probably doesn't work for you.

Not to worry. I have a documentation.

Importing stuff into this app

Upon dragging the files into this app, the tool will load the files and populate the Render passes list. If there's more than one option, you need to figure out which one has the meshes you want. Through the magic of trial and error, though usually the geometry you want is going to appear in the FORWARD (or G-buffer) pass with the highest number of draws.

If you're importing RenderDoc capture, the import will be quick. If you're importing Intel GPA export, things will take a bit longer.

Input options are set to reasonable defaults. This app uses 1 unit = 1 meter scale internally. If you know what scale your game is using, you can define capture unit size in order to correct for that. You do not have to do this, as nothing will break (at least, not too much) if you keep this option as it is.

Input geometry axis mapping can different from game engine to game engine. You'll only see if it's set wrong once the scene is loaded and you see your scene mirrored, rotated sideways, or both.

If you exported your scene with RenderDoc, Hide largest % of objects should probably be at around 5% in order to get rid of the skybox and other large salad. If you exported with Intel GPA, you should keep this option at 0% and increase it only if necessary. This slider can also be changed after the scene is loaded, so don't worry too much about getting it wrong.

"Enforce max scene size" is for when things start breaking because you didn't set capture unit size and the scene gets too big. This option ensures the scene is no more than (value of next field) units across.

Click 'reconstruct scene' button to load your scene.

Scene viewer

The scene viewer consists of main toolbar (Import, export, help, control options — these are self-explanatory), object sidebar, main viewport, and viewport toolbar.

In the objects sidebar, you can see the "hide largest % of objects" slider (which you should change if your view is blocked by skybox, or if the scene is missing objects that don't appear even though you know you most definitely exported them). After that, you can see the list of objects/draw calls.

Clicking on an object will select it. Clicking the sel button adds or removes the object from selection (shift-click and control-click also work). Clicking the vis: button toggles visibility of that object. If more objects are selected, visibility of all selected objects will be toggled.

Note that objects hidden with the Hide largest % of objects slider aren't selectable.

In the main viewport, movement works like Plasticity with Blender settings. Middle mouse rotates the scene around a pivot (unlike in Blender, pivot is the surface of the object under your mouse cursor) and shift + middle mouse pans the scene. (Ctrl + middle mouse to zoom is not implemented — use mouse scroll instead).

Pressing A toggles fly mode. Use ESDF to move around, space to move up, and control to move down. Mouse movement controls the camera orientation. Press A or escape to exit fly mode.

You can switch to WASD controls in Control options menu. In WASD, fly mode toggle is F.

You can also select objects by clicking them in the scene. As usual, shift + click and control + click behave as you would expect. You can select multiple objects with lasso tool, which becomes active when you click and drag. As usual, shift and ctrl do what you expect them to do.

Select by volume opens a toolbar that allows you to spawn a shape (either sphere or a cube). You can then select all the objects within said shape. Read the UI, it's self-explanatory. You can resize shapes by pressing S and grabbing a handle, or move them by pressing G and grabbing a handle. If you selected a cube, you can also rotate the cube by pressing R.

If using RenderDoc, you will see a Distortion fix option in the viewport toolbar. In general, the app should have corrected scene distortion automatically. If you think the scene still doesn't look right (i.e. if you think the proportions of objects in scene aren't correct), you can go to Distortion fix → Select distortion correciton landmark. Start clicking objects in the scene. When you click an object, an object preview panel will appear. If the object inside the preview panel matches its appearance in game, click Fix distortion button. If not, try a different object.

If the scene appears sideways (rotated by 90° (that's 194° for fellow Americans)), go to Scene orientation → Set axis mapping and play around until the scene looks right. If the scene appears mirrored, flip the sign of ONE of the axes (e.g. change +z to -z, or -y to +y).

If the scene appears tilted by any amount other than 90°, go to Scene orientation → Select ground plane and pick three points on a flat, horizontal surface. If everything looks fine, click Confirm plane. You should also know what button to press if the scene appears upside down.
